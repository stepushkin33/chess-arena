# Как устроен Chess Arena

Три npm workspaces: `client` (React/Pixi), `server` (Nest), `shared` (правила и протокол).
Сервер владеет состоянием партии. Клиент показывает его и отправляет намерения игрока.
Чистые шахматные функции не зависят от React, Nest или сети.

## Карта ответственности

| Область            | Код                           | За что отвечает                                                         |
| ------------------ | ----------------------------- | ----------------------------------------------------------------------- |
| Правила            | `shared/src/chess`            | Генерация ходов, переход позиции, шах/мат, повторения, заявления ничьей |
| Контракт           | `shared/src/protocol.ts`      | Команды клиента и события сервера как discriminated unions              |
| HTTP               | `server/src/web`              | Раздача сборки, кеширование ресурсов, entrypoint прямых ссылок          |
| WebSocket          | `server/src/transport`        | Origin, heartbeat, лимит команд, ошибки, персональная рассылка          |
| Подключения        | `server/src/connections`      | Соответствие сокета и connectionId                                      |
| Сценарии           | `server/src/rooms`            | Членство, игра, предложения, гостевой счёт                              |
| Сессия клиента     | `client/src/entities/session` | Комната, соединение, переходы состояния                                 |
| Взаимодействия     | `client/src/features`         | Выбор хода, вход, подтверждения действий, приглашение                   |
| Представление игры | `client/src/entities/game`    | Общие SVG, история, взятия, Pixi-сцена                                  |
| Композиция         | `client/src/widgets`, `pages` | Сборка интерфейса из самостоятельных блоков                             |

## Клиент: композиция и границы состояния

`App.tsx` подключает `SessionProvider` и выбирает одну из трёх страниц.
`RoomPage` содержит только композицию: шапку, доску, боковую панель и уведомления.
Страница не принимает десятки полей и обработчиков.

`SessionProvider` разделяет два контекста: снимок комнаты/соединения и действия `send/leave`.
В нём нет выбранной клетки, состояния модалок или флагов копирования ссылки.
Это общее состояние сессии, а не универсальный store для всех деталей интерфейса.

- `useSessionConnection` связывает reducer с транспортом, URL и переподключением.
- `useGameSocket` — React-адаптер для `createGameConnection`. Транспорт управляет
  сокетом и таймером повторного подключения. Отменённый эффект не прерывает незавершённый
  HTTP upgrade: после handshake устаревшее соединение закрывается обычным close-frame.
- `sessionReducer` описывает переходы явно. Например, поздний game_state не открывает
  комнату повторно после выхода. Его можно тестировать без браузера.
- `useRoomEntry` владеет запросом имени и выбором create/join.
- `useBoardSelection` владеет выделенной клеткой, превращением и заявлением ничьей с ходом.
- `useGameActions` владеет подтверждением сдачи/ничьей и доступностью кнопок.
- `useRoomInvite` владеет Web Share/clipboard и временным сообщением о копировании.
- `Modal` отвечает только за portal, фокус, Tab, Escape и восстановление фокуса.
  Смысл кнопок определяет feature.

Структура слоёв следует FSD: `pages → widgets → features → entities → shared`.
Виджеты не импортируют соседние виджеты; features не читают внутренности друг друга.
Игра и сессия — связанные доменные сущности: сессия использует форматирование игры.
Компоненты отображения принимают небольшие предметные параметры (`moves`, `player`,
`view`), а не большой набор несвязанных флагов. У Pixi `BoardView` — явный снимок
того, что надо нарисовать, без команд комнаты.

Стили разделены в `app/styles` по областям: базовые элементы, лобби, шапка,
доска, боковая панель, диалоги, дополнительные элементы и адаптация.
`styles.css` задаёт порядок их подключения.

## Путь одного хода

1. Клетка Pixi вызывает обработчик с игровыми координатами.
2. `useBoardSelection` показывает разрешённые варианты или отправляет typed-команду `move`.
3. `useGameSocket` формирует JSON `{event, data}` и отправляет его на `/ws`.
4. `ChessGateway` сопоставляет событие со сценарием `RoomGame.move`.
5. Сценарий проверяет игрока, второго участника, очередь, формат и вызываeт `makeMove`.
6. `RoomSocketTransport` превращает результат сценария в персональный DTO каждому игроку.
7. Reducer сохраняет новый снимок комнаты. React передаёт доске новый `BoardView`.
8. Сцена обновляет подсветку и анимирует перемещение спрайтов.

Подсветка клиента не разрешает ход: сервер повторно проверяет правила. Специальные
флаги «рокировка» и «взятие на проходе» сервер выводит из легального хода самостоятельно.

## Pixi.js: начать здесь

Читайте `entities/game/ui/ChessBoard.tsx`, затем файлы `entities/game/lib/pixi`.

- `coordinates.ts` отделяет игровые координаты от экранных. `a8` всегда
  `{row: 0, col: 0}`, даже на повёрнутой доске.
- `piece-textures.ts` загружает SVG через `Assets.load` и разделяет текстуры между досками.
- `board-scene.ts` создаёт один `Application`, добавляет клетки, подсветку, фигуры,
  подписи и регистрирует `pointertap`. Декоративные слои имеют `eventMode = 'none'`.
- `highlights.ts` перерисовывает подсветку без пересоздания canvas.
- `piece-layer.ts` хранит `Sprite`, перемещает их через requestAnimationFrame за 240 мс
  и анимирует обе фигуры при рокировке. Учитывается prefers-reduced-motion.

React-адаптер создаёт сцену при монтировании, вызывает `update(view)` при изменениях
и `destroy()` при размонтировании. Application не создаётся на каждый клик.
Сцена не уничтожает общие текстуры при закрытии доски. SVG Cburnett используются также
в истории, взятых фигурах, подсказках и выборе превращения; шрифты устройства не влияют
на внешний вид фигур.

## Nest.js: начать здесь

`main.ts → AppModule → RoomsModule → ChessGateway` показывает запуск и регистрацию DI.

| Класс                 | Единственная основная ответственность                                   |
| --------------------- | ----------------------------------------------------------------------- |
| `ChessGateway`        | Прочитать событие и вызвать сценарий                                    |
| `RoomSocketTransport` | Исполнить команду на соединении, обработать ошибку, разослать результат |
| `ConnectionRegistry`  | Хранить подключения и обратный индекс по сокету                         |
| `RoomMembership`      | Создать комнату, присоединить или удалить участника                     |
| `RoomGame`            | Применить ход, сдачу или заявление ничьей                               |
| `RoomOffers`          | Единый жизненный цикл предложений ничьей/реванша                        |
| `RoomAccess`          | Найти комнату игрока и проверить общие предусловия                      |
| `RoomStore`           | Хранилище комнат в памяти                                               |
| `Scoreboard`          | Начислить победу один раз и запомнить гостевой счёт                     |
| `room.presenter.ts`   | Построить публичный DTO без сокетов и внутренних connectionId           |

Сервисы возвращают `RoomChange` или `RoomDeparture`, а не отправляют JSON самостоятельно.
Предложение хранится одним `RoomOffer | null`: невозможно одновременно ждать ничью
и реванш. Предсказуемые бизнес-ошибки имеют тип `RoomError`; неожиданные ошибки
записываются в серверный лог, пользователю отправляется безопасный общий текст.

`@Module` регистрирует providers. Явные `@Inject` в конструкторах сохраняют работу DI
также в dev-сборке через tsx. Тестовая fixture собирает те же зависимости напрямую,
без HTTP-сервера. Отдельные тесты проверяют членство, игру и предложения.

## Один процесс для Render

`npm run build` собирает shared, Nest и React. `npm start` запускает обычный Node.
Nest раздаёт `client/dist` и обрабатывает `/ws`, `/health`, `/`, `/room/:roomId`.
Путь сборки вычисляется относительно файла модуля и не зависит от рабочей папки shell.

Публичный адрес берётся из `PUBLIC_URL` или автоматически из `RENDER_EXTERNAL_URL`.
Браузер использует `location.host` для WebSocket и `location.origin` для приглашений.
Хешированные ресурсы кешируются надолго, HTML — с перепроверкой.
Неизвестные API/ресурсы возвращают 404, а не HTML приложения.

## Как изучать и проверять

Поставьте breakpoint в `RoomGame.move`, откройте два окна и проследите путь хода.
Затем измените длительность в `piece-layer.ts` или цвет подсветки в `highlights.ts`.
Для знакомства с DI замените provider хранилища, сохранив API сценариев.

`npm test` проверяет правила, серверные сценарии, окружение и reducer сессии.
`npm run test:smoke` после сборки запускает настоящий production-сервер, проверяет
HTTP, прямые приглашения, кеширование, Origin и обмен WebSocket между игроками.
`npm run test:dev` проверяет ту же связь через настоящий Vite proxy, разрывы во время
handshake и автоматическое восстановление клиентского соединения.
Комнаты и счёт пока не переживают завершение процесса; гостевой ID не является аккаунтом.
