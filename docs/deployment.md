# Бесплатный деплой на Render

Проект запускается одним **Web Service / Node / Free**. Nest раздаёт собранный React,
SVG-фигуры и обслуживает WebSocket на том же адресе. Отдельный Static Site или база данных
для этой версии не нужны. Все команды выполняются через npm.

## 1. Загрузить проект на GitHub

Создайте репозиторий, в корне которого находятся `package.json`, `package-lock.json`,
`render.yaml`, `.nvmrc` и каталоги `client`, `server`, `shared`.
Загрузите исходники и lock-файл. `node_modules`, `dist`, `.env` и ключи загружать не нужно:
они исключены через `.gitignore`. Git-репозитория в папке проекта пока нет — его нужно создать.

Перед отправкой из корня проекта:

```bash
npm ci
npm run format:check
npm run lint
npm test
npm run build
npm run test:smoke
```

## 2. Создать сервис

В [Render Dashboard](https://dashboard.render.com/) нажмите **New → Web Service**,
подключите GitHub и выберите репозиторий и ветку проекта.

| Поле               | Значение                                                           |
| ------------------ | ------------------------------------------------------------------ |
| Name               | Любое свободное имя, например `chess-arena`                        |
| Language / Runtime | **Node**                                                           |
| Branch             | Ветка с вашим проектом                                             |
| Root Directory     | Оставить пустым, если `package.json` находится в корне репозитория |
| Build Command      | `npm ci --include=dev && npm run build`                            |
| Start Command      | `npm start`                                                        |
| Instance Type      | **Free**                                                           |
| Health Check Path  | `/health` (в Advanced или Settings)                                |

Из-за наличия Dockerfile Render может предложить Docker: выберите именно **Node**.
Если вы загрузили проект в подпапку репозитория, Root Directory должен указывать на
эту подпапку целиком, а не на `client` или `server`.

## 3. Проверить переменные окружения

Добавьте в Environment:

```dotenv
NODE_ENV=production
NODE_VERSION=22.23.4
```

Render сам задаёт `PORT` и `RENDER_EXTERNAL_URL`. Сервер слушает `0.0.0.0:$PORT`
и разрешает WebSocket с публичного адреса сервиса. Для стандартного адреса Render
не задавайте `PUBLIC_URL`, `ALLOWED_ORIGINS` или `HOST`: они не требуются.
TypeScript, Vite и прочие инструменты сборки устанавливаются благодаря `--include=dev`
даже при `NODE_ENV=production`.

## 4. Запустить и проверить

Нажмите **Deploy Web Service**. Дождитесь успешной сборки и статуса **Live**.
Render выдаст адрес вида `https://имя-сервиса.onrender.com` с HTTPS.

1. Откройте адрес сервиса: должен появиться стартовый экран Chess Arena.
2. Откройте `/health` на этом же домене: ожидается `{"status":"ok"}`.
3. Создайте комнату, укажите имя: URL изменится на `/room/КОД`.
4. Отправьте приглашение и откройте его в другом браузере или на телефоне.
5. Сделайте ходы с обеих сторон, проверьте ничью и новую партию.

WebSocket автоматически использует `wss://текущий-домен/ws`. Приглашения используют
текущий домен. В браузерной сборке нет фиксированного адреса компьютера или API.

Следующие push в выбранную ветку запускают новый деплой. Он прерывает текущие партии,
так как комнаты и гостевой счёт хранятся в памяти процесса.

## Вариант: Blueprint

В корне есть `render.yaml` с теми же настройками. Вместо ручного заполнения выберите
**New → Blueprint**, подключите репозиторий, проверьте план **Free** и примените Blueprint.
Это альтернативный способ создания того же одного сервиса; оба варианта одновременно
использовать не нужно. Если проект лежит в подпапке, сначала адаптируйте пути Blueprint.

## Ограничения Free

- После 15 минут без входящих HTTP-запросов или WebSocket-сообщений сервис засыпает.
  Следующее открытие может занять около минуты.
- Сон, рестарт или деплой завершают процесс: комнаты, партии и гостевой счёт теряются.
  Старая ссылка может показать «Комната не найдена»; создайте новую комнату.
- Есть общие месячные квоты: 750 часов Free-инстансов на workspace, а также лимиты
  трафика и сборок. Проверяйте их в Dashboard → Usage.
- Для этой реализации нужна одна реплика. Сохранение партий, авторизованные аккаунты
  и общее хранилище для нескольких реплик требуют отдельной доработки.

Для личных партий это позволяет начать бесплатно. Для постоянного сервиса потребуется
хранилище и тариф, соответствующий нагрузке.

## Свой домен (необязательно)

Бесплатного адреса `onrender.com` достаточно. Если у вас уже есть домен, добавьте его
в **Settings → Custom Domains** и создайте DNS-записи, которые покажет Render.
После подтверждения DNS задайте `PUBLIC_URL=https://ваш-домен` и выполните redeploy.
Если нужны оба адреса, задайте `ALLOWED_ORIGINS` как список точных HTTPS-origin через
запятую, без путей и завершающего слеша. Сертификаты обслуживает Render.

## Если деплой не работает

| Симптом                               | Что проверить                                                                |
| ------------------------------------- | ---------------------------------------------------------------------------- |
| Запускается Docker-сборка             | Language должен быть Node                                                    |
| Не найден workspace/package.json      | Root Directory должен содержать все три workspace                            |
| Не найден Vite или tsc                | Build Command должен содержать `npm ci --include=dev`                        |
| Client build is missing               | Нужен корневой `npm run build`, который собирает сервер и клиент             |
| Страница работает, WebSocket отклонён | Удалите старые `PUBLIC_URL` / `ALLOWED_ORIGINS` или задайте актуальный домен |
| После паузы долго открывается         | Дождитесь пробуждения Free-инстанса                                          |
| Старая комната исчезла                | Процесс был перезапущен или заснул; создайте новую комнату                   |

Схема Docker/Caddy для собственного VPS сохранена в [отдельном руководстве](deployment-vps.md).
